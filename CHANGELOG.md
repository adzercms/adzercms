# Changelog

Notable changes of the engine packages. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- First public version: the core, contracts, project template, admin, cabinet, theme and the modules listed in [What's in the repository](README.md#whats-in-the-repository)
- `adzercms/morphology`: Russian word form analysis — the pymorphy3 analyzer in PHP gives every parse of a token of letters and digits with its OpenCorpora tag, normal form and score as pymorphy3 does; the dictionary is `adzercms/morphology-ru`
- Panel layout `brand.layout`: sections on the side or in a bar under the header; fragment place `Fragment::TOP` of the top layout: its fragments replace the panel header, the admin bar and the sidebar
- `adzercms-refresh` reinstalls the installed packages whose patches changed in `patches.lock.json` of cweagans/composer-patches
- The theme file field sends the picked file to the server at once with progress in the field; the form takes it under the field name as before, a dialog form sent before the upload ends closes at once and goes when the upload ends, its row in the list shows the progress; leaving the page earlier asks first
- The admin section "Translations": the admin changes any text of the enabled packages in each language of the catalogs without code, the language of the instance first, clearing it brings back the catalog text
- `BotListener`: a feature module takes what people send to the bots
- `adzercms/pages`: site pages of blocks in order on the theme site frame — hero, advantages, text, questions with FAQPage, call to action and block types of other modules through the `AdzerCMS\Pages\Block` service, a header menu, the pages in the sitemap
- Setting field types `Type::Markup` — GitHub-flavoured Markdown shown by the `markup` Twig filter without raw HTML and unsafe links, and `Type::Rows` — rows of the fields it declares
- `LoginListener`: a feature module that waits for a login takes the profile of the login service instead of the entry
- `UserPlaces` and `UserCreation`: the new user form of the admin creates a user at a place of a feature module, such as a site the instance serves, and a feature module closes creating users on the instance itself
- `Contacts`: one core check of the phone and email of a user for the admin and modules that create or change users, a malformed contact or one held by another user is refused with the holder named
- `Roles`: the admin picks the role of a user only when a feature module has a section in the cabinet, otherwise the user form has no role field, a user the admin creates is an administrator and a saved user keeps the role
- `Traffic`: an analytics counter module gives the admin section "Traffic" the visitors, visits and views of a month, a year or own dates by days, weeks or months under the total of the period; the Yandex Metrica module reports them from its counter by a token with `metrika:read`
- Notice channels of modules: a feature module brings its own channel after the bots
- Sums carry the ruble sign in the reader's language through ICU: the `money` and `precise` filters, `Money::rubles()` and `Money::precise()` give a translatable `Sum` for phrase arguments
- Setting field `Type::Color`: the admin picks the color in the browser's color picker, the setting keeps `#rrggbb`
- Setting field `Type::Photo`: a JPEG, PNG or WebP photo of any size, the core turns it upright, scales it down to its side and keeps it as WebP without metadata; it uploads, goes out and drops as a `Type::Image` setting, `Type::picture()` tells both
- Variants of a `Type::Choice` setting field from data: `choices:` takes a closure that the form and the value check call, `Field::choices()` gives the variants; the package console runs without a database, so the field list reads no data
- Settings section with a menu on the left: the System pages of `AdzerCMS\Contracts\Setting\Page` — General, Branding, Mail and notices, Extensions — take core fields by `page:`; an enabled module with fields or a block of its page gets its own page titled by the module, a feature module under Modules, a kind module under Integrations by its kind, in title order; the module card and the heading of the module's sections lead to its page; fields without a section open a page, labels and fields of a row line up; the Extensions page carries the extension catalog address and the module sources, which leave the Extensions section; fragment place `Fragment::ADMIN_SETTINGS_MODULE` with the module key: blocks of the module's settings page under its fields
- Module title `extra.adzercms.title.<language>` in every engine language: the module card and its settings page show it in the reader's language, `adzercms-check` refuses a module without it
- File field `@Theme/_file.html.twig`: a button in the language of the page and the picked file names over the native field, which keeps drag and drop and form validation
- Fragment place `Fragment::CABINET_PROFILE`: the profile under the contacts
- Manual order of a list `Order`: rows are dragged by a handle within their group with SortableJS, the list posts the new order to its route; `Order::place()` puts the moved ids into the places they held
- Going back closes a modal dialog by the gesture and the browser button: the core script `adzercms/dialogs` keeps a history entry per open dialog, the theme imports it
- `Table::paginate()`: a listing that fetches a collection of its rows pages with the offset paginator of Doctrine ORM and takes the total from it
- A renamed namespace of a migration set or a migration moved to another set does not run again: the migrations console moves its mark to the migration with the same version number
- String equality tells letters apart by diacritics, «е» from «ё», on every database: the migrations console gives a MySQL database `utf8mb4_0900_as_ci` and a MariaDB one `utf8mb4_uca1400_as_ci`, converting the tables of another collation
- The verified mark in the module catalog: the version whose commit passed the module check of the engine; installing or updating to a version without it asks for confirmation, the `confirm` key of a row action gives the question
- `adzercms-module-check` checks an installed module: the build with it, `composer audit` of the packages it adds, PHPStan and Psalm taint analysis of its code; the project template requires Psalm with its Symfony plugin for development
- A refresh holds the site from its start, a module request from moving the staged copy, until the build switch: it waits for the running requests and jobs, a new request gets 503 with `Retry-After`, a new job waits; the entries `public/index.php` and `bin/console` of a site require `config/hold.php` of the project template before `vendor/autoload_runtime.php`
- A changed `composer.lock` or `patches.lock.json` reaches the site after the check of a copy of the tree by the check script of the copy, so an update brings its own check: its dependencies with the changed patches, the importmap packages, `adzercms-check` and every test suite in its own process by `adzercms-suites`
- `adzercms-check` checks the translation catalogs of each package with its module enabled: the same keys in every language, every key of its code and templates in the English catalogs of the package or of the modules it enables
- `TextResponse`: a plain text response that the Psalm taint analysis of the module check doesn't take for HTML
- The cabinet home lives at `/cabinet`: the root of the instance is the public home of a feature module, without one it leads to the cabinet home; a login without an interrupted page leads to the cabinet home
- Theme preview: an installed theme opens on the pages of the site to the admin only before it is enabled; the module operation builds the preview with `adzercms-build --preview` of the core, the bar of the preview leads out of it; `adzercms:sweep` removes the static of module sets without cache
- Bounce mailbox on the Mail and notices tab: a notification letter goes with a signed subaddress of the mailbox as the envelope sender, `adzercms:notices` reads the mailbox over IMAP with directorytree/imapengine and turns a failed delivery report into a failed notice; the bounced address of a record is marked undeliverable and gets awaited letters only until the address changes or its check link is confirmed; the cabinet names the bounce in the mail cell with the check and asks on its home to change the mail, a mail change asks no consent of the undeliverable address, the admin shows the mark with its reason and moment in the profile
- `adzercms:showcase` gives the project site the public values as a JSON object of sections, the scheduled `adzercms:showcase:file` replaces the file named by `SHOWCASE_FILE` with them atomically: the `core` section holds the absolute cabinet home, registration, password reset and profile addresses and the settings of the enabled analytics counters, a module adds its section under its lowercase key with a `Showcase` service of its bundle namespace; the support module gives the addresses of the tickets and of a new ticket
- Admin entries `AdminEntry::Users`, `AdminEntry::Modules` and `AdminEntry::ModuleSettings`: a module reaches the user list, the modules section and its settings page of the admin without naming their routes
- Rescan button `@Theme/_rescan.html.twig`: a block from a snapshot of an outside service polls it again, the table filters go along
- The Content Security Policy allows media of the site's own origin by `media-src 'self'`: a `<video>` or `<audio>` of a module plays its own files
- A module cell `Cell` of a foreign listing carries bold text, a note in brackets, a warning mark with its text on hover and further parts with their own signs; the theme `cell()` draws it; the admin user list shows the login as a link to the card, the contact and the registration last
- `adzercms-suites --changed <base>` runs only the suites of the packages and modules changed since the base commit and of their consumers by the `composer.json` requirements; a change outside them other than documentation and browser tests, or an unknown base, runs every suite; CI takes it on pushes and pull requests, the weekly run stays full
- `Photos` keeps the photos of module records: a JPEG, PNG or WebP turned upright by EXIF, scaled down to the side of the module and stored as WebP without metadata under a random name, found and dropped by its names; `ImmutableFileResponse` serves such a file with a public cache for a year and answers a matching ETag with 304, a session of the request keeps the cache
- `PublicForm`: a visitor form of a feature module takes the core guard — a hidden trap field `trap_field()` taken without a record, a limit of submissions of the form from one address, and the privacy policy line `privacy_note()` under the send button; the lead window takes it
- Link card `/brand.png`: the `og:image` of the theme head is the brand logo in the middle of a PNG of 1200×630, white or dark — the one that loses fewer pixels of the logo, an SVG logo drawn at the card size, so messengers that skip SVG (Telegram among them) show it; without the `imagick` extension the head carries no `og:image`
- PDF documents of modules: the `@Core/document/page.html.twig` page with the `doc` base styles shared with the in-page view, `PdfDocuments` renders a template to a file through the selected PDF module and answers it with an ASCII fallback name; `Brand::paperLogo()` gives the logo as a `data:` address, a theme-colored SVG in the colors of the link card
- `adzercms/leads`: commercial offer of a lead as a PDF opened in a new tab — brand, number and date, client, subject, sum, manager with contacts and the validity of the `leads.offer_days` setting; without a PDF module the lead page has no offer button

### Security

- Sign-in through a login service finds a user, fills empty contacts and creates a user only by a phone or email the service vouches for: `Profile::$phoneVerified` and `Profile::$emailVerified`, set by the login module from the service's verification claim or from the service binding the contact only after confirming it. Before, a profile carrying someone else's unverified phone or email signed in to that person's account. An unvouched contact of another user now turns the sign-in away; the Telegram, Sber ID, VK ID and Yandex ID modules vouch for the phone, the Yandex ID module also for the mailbox of its own login on a Yandex mail domain
