# Разработка движка

[English](engine-development.md) | Русский

Как устроен движок и каким правилам следуют его код и тесты. Контракты модулей — в разделе [Свой модуль](module-development.ru.md).

## Монорепозиторий

- У `packages/<имя>/` namespace `AdzerCMS\<Имя>\` из `src/` и тесты под `AdzerCMS\<Имя>\Tests\`, остальное — по [Раскладке пакета](module-development.ru.md#раскладка-пакета).
- `contracts` — `library` под SemVer, `core` — `symfony-bundle`, `skeleton` — шаблон проекта, все прочие пакеты — `adzercms-module`.
- Приложение разработки берёт `packages/*` path-репозиторием.
- Пакеты `symfony/*` держатся одной линии LTS, её задаёт `extra.symfony.require`.
- `composer install` и `composer update` ставят JavaScript-библиотеки каждого пакета движка с `importmap.php` в `assets/vendor/`.
- Выпуск — тег SemVer `v<версия>` на `main`, общий для всех пакетов; `main` пакета — псевдоним `<major>.<minor>.x-dev` следующего выпуска в `extra.branch-alias`.
- Новому пакету нужен его репозиторий только для чтения до первого push с ним: назовите пакет в pull request, репозиторий заведут сопровождающие.

## Ядро и модули

- Ядро ведёт реестр модулей, учётные записи и вход, настройки и секреты, оповещения. Всё остальное — модули: функции — модули функций, сменные части и внешние сервисы — модули родов.
- Роды ядра — `AdzerCMS\Contracts\Module\CoreKind`: админка, кабинет и тема по одному модулю, вход через сервис, шлюз сообщений на телефон, бот мессенджера, проверка «не робот» и модули функций перечнем. Модуль функции объявляет свои роды своим пакетом: эквайринг у `payments`, сервер обновлений в реальном времени у `realtime`.
- Ядро зовёт модуль только через интерфейсы: не знает ни реализации, ни сущностей и маршрутов модуля, в его шаблонах и запросах нет полей модуля. Модуль отдаёт готовые фрагменты и значения ячеек; пустой фрагмент не выводится.
- Сущности модуля живут в его собственных таблицах с приставкой модуля и ссылаются на записи ядра и друг на друга.
- Ядро держит модуль ссылкой, модуль держит службу ядра замыканием: обратная ссылка даёт круг в контейнере.
- Экземпляр собирает только выбранные модули: служб и команд прочих в его контейнере нет. Величины модуля живут в его классах, конфигурация ядра параметров модулей не держит.
- Служба с интерфейсом контракта регистрируется автоконфигурацией: интерфейсы `adzercms/contracts` помечает бандл ядра, интерфейс пакета модуля несёт `#[AutoconfigureTag]` в `src/` этого пакета.
- Действие либо операция отказывает через `AdzerCMS\Contracts\Refusal`: причина человеку и маршрут устранения с его параметрами. Строкой операции не отказывают, а страницы идут по маршруту, не разбирая причину.
- Шаблоны рода с одним модулем лежат ещё и в пространстве ключа рода: `@Theme`, `@Admin`, `@Cabinet`. Шаблоны других модулей адресуют выбранный модуль рода, не его пакет.
- Страница модуля функции даёт только содержимое: каркас, навигация и компоненты визуального языка приходят из темы по имени шаблона, страница их разметку не повторяет.

## Код

- Движок работает на MySQL, MariaDB и PostgreSQL. Запрос — DQL либо построитель запросов DBAL. Имена таблиц, колонок и псевдонимов — не зарезервированные слова; миграции не называют collation.
- Миграция следует [Миграциям](module-development.ru.md#миграции) и принадлежит набору владельца правящейся таблицы. Величины — литералами, namespace набора не переименовывается, номер версии не повторяет занятый другим набором. Миграция идёт после кода, которому служит.
- Перечень берёт строки, значения модулей и вложенные коллекции одним запросом на страницу, а не запросом на строку.
- Деньги — `DECIMAL` с `bcmath`, вывод — денежными помощниками ядра.
- Текущий момент — Symfony Clock: `now()` и `DatePoint` в коде, `now()` в шаблонах, `sleep()` часов для ожидания.
- Строка человеку — ключ каталогов своего пакета в ICU MessageFormat, запасной язык — английский. Контракт принимает `TranslatableInterface`. Сообщения разработчику, вывод консоли и тексты гейтов — английские и не переводятся.
- Изменяющий запрос несёт токен CSRF полем `_token`. Имена полей формы — без точек.
- Content Security Policy разрешает только своё происхождение; модуль добавляет источники через `ContentSource`. Обработчики событий живут в файлах скриптов и находят цели по data-атрибутам, скрипты — ES-модули в `public/` пакета, сторонние библиотеки — из `importmap.php` пакета.
- Файлы, создаваемые приложением, лежат под параметром `adzercms.files_dir`; дерево кода — только для чтения.
- Консольная команда берёт тело либо секрет из stdin по своему флагу, никогда аргументом.
- Задание выходит с ненулевым кодом только при своём отказе; состояние внешних объектов — его вывод.
- Служба, копящая ответы либо сущности на время запроса, реализует `ResetInterface`.

## Гейты

Хук pre-commit гоняет гейты экземпляра из раздела [Git и обновления](installation.ru.md#git-и-обновления), включая текущий момент мимо Symfony Clock, и сверх них отказывает коммиту, когда:

- `README.md` либо файл `docs/` меняется без своего перевода `*.ru.md`
- файл `packages/skeleton/` и одноимённый файл корня, равные в `HEAD`, меняются порознь

`vendor/bin/adzercms-check` гоняет проверки всего дерева: стиль кода, PHPStan на уровне `phpstan.dist.neon`, XLIFF, ICU и Twig каждого пакета. Находка PHPStan устраняется причиной, не `ignore` и не baseline. [CI](../.github/workflows/ci.yml) гоняет проверки и все наборы на MySQL, MariaDB и PostgreSQL со всеми поддерживаемыми версиями PHP на каждый push в `main` и каждый pull request.

## Тесты

- Набор — пакет, названный ключом своего модуля; наборы — имена `<testsuite>` в `phpunit.dist.xml`. Прогон без `--testsuite` берёт только набор по умолчанию, и `--list-suites` называет только его: гоняйте поимённо набор изменённого пакета и наборы пакетов, которые им пользуются.
- Набор выбирает модули как в разделе [Тесты](module-development.ru.md#тесты) модуля; прочие роды пусты.
- Тест, чьё ожидание держится на поле, колонке, факте либо сообщении модуля, живёт в пакете этого модуля. Тест ядра либо модуля функции верен при любом модуле рода; нужный ему модуль рода — фикстура окружения теста: `config/services_test.php` корня и бандлы-фикстуры тестов ядра.
- Каждый тест идёт в транзакции с откатом после него, поэтому ожиданий на номер записи нет. Тест миграций ядра накатывает миграции на пустую базу и сверяет схему с метаданными.
- Помощники тестов ядра: `SchemaTestCase` — основа тестов на базе, `reread()` берёт сущность, записанную запросом; трейты `Browser` (токен формы, вход, второй браузер, фрагменты, отправка форм, ячейки перечня, плитки, тосты, файлы загрузки), `Container` (типизированные службы, параметры, команды, переведённые фразы), `Queries` (`assertListingKeepsItsQueries()` против N+1), `Configuration` (настройки экземпляра), `Delivery` (отправленные письма и сообщения), `Accounts` (записи); `HttpAnswers` отдаёт ответы внешних сервисов в `MockHttpClient`.
- Заглушка внешней системы отвечает протоколом, снятым с живой системы, вместе с её отказами.
- День сценария фиксирует `mockTime()` часов моментом строкой в поясе PHP.
- Обход экранов `tests/browser/` проходит админку и кабинет живого экземпляра на узком и широком экране: `tests/browser/run.sh` с `ADZERCMS_URL`, `ADZERCMS_LOGIN` и `ADZERCMS_PASSWORD` оператора. Страница падает на рваной раскладке, ответе с ошибкой, ошибке консоли либо повторе `id`; изменяющие формы не отправляются.

Грабли:

- Служба подменяется один раз и до первого обращения контейнера к ней.
- `KernelBrowser` поднимает новый kernel между запросами: подменённая служба и взятая раньше сущность теряются. Держите kernel через `disableReboot()` либо берите запись из контейнера текущего запроса.
- Слушатель Doctrine не зависит от служб, которые подменяет тест: его поднимает первый flush.
- Symfony CssSelector не разбирает `:has()`.
- Фрагмент перечня берётся запросом с заголовком фрагмента: страница отдаёт только место под него.
- Письма считаются за последний запрос: переход по redirect обнуляет счёт.
- Находка PHPStan, пропадающая с чистым `tmpDir`, — устаревший кеш: удалите `tmpDir`.
