# Разработка движка

[English](engine-development.md) | Русский

Правила, по которым пишутся код и тесты самого движка. Как сделать свой модуль, рассказано в разделе [Свой модуль](module-development.ru.md).

## Монорепозиторий

- Каждый пакет лежит в `packages/<имя>/`: код — в `src/` с namespace `AdzerCMS\<Имя>\`, тесты — в namespace `AdzerCMS\<Имя>\Tests\`. Остальные каталоги устроены так, как описано в разделе [Раскладка пакета](module-development.ru.md#раскладка-пакета).
- `contracts` — библиотека (`library`) с версиями по SemVer, `core` — бандл Symfony (`symfony-bundle`), `skeleton` — шаблон проекта. Все остальные пакеты — модули (`adzercms-module`).
- Приложение для разработки подключает `packages/*` как path-репозиторий.
- Все пакеты `symfony/*` держатся одной LTS-версии, её задаёт `extra.symfony.require`.
- `composer install` и `composer update` ставят JavaScript-библиотеки из `importmap.php` каждого пакета в `assets/vendor/`.
- Выпуск — тег SemVer `v<версия>` на `main`, один на все пакеты. В `extra.branch-alias` ветка `main` каждого пакета названа `<major>.<minor>.x-dev` следующего выпуска.
- Каждый пакет публикуется в свой репозиторий только для чтения `adzercms/<имя>` и на Packagist. Новому пакету оба заводятся первым push в `main` с этим пакетом.

## Ядро и модули

- Ядро отвечает за реестр модулей, учётные записи и вход, настройки и секреты, уведомления. Всё остальное делают модули: функции сайта — модули функций, заменяемые части и внешние сервисы — модули видов.
- Виды ядра перечислены в `AdzerCMS\Contracts\Module\CoreKind`. Админка, личный кабинет и тема подключаются по одному модулю, а вход через сервис, отправка SMS, боты мессенджеров, капча и модули функций — списком. Модуль функции может объявить свои виды в своём пакете: так `payments` объявляет эквайринг, а `realtime` — сервер обновлений в реальном времени.
- Ядро обращается к модулю только через интерфейсы. Оно не знает ни реализацию модуля, ни его сущности и маршруты, а в шаблонах и запросах ядра нет полей модулей. Модуль отдаёт готовые фрагменты страниц и значения ячеек; пустой фрагмент не выводится.
- Сущности модуля хранятся в его собственных таблицах с префиксом модуля и могут ссылаться на записи ядра и друг на друга.
- Ядро держит модуль по ссылке, а модуль получает сервис ядра через замыкание: прямая ссылка в обратную сторону замкнула бы контейнер в цикл.
- Экземпляр собирает только включённые модули: сервисов и команд остальных в его контейнере нет. Значения, которые нужны модулю, живут в его классах, а конфигурация ядра параметров модулей не хранит.
- Сервис, который реализует интерфейс контракта, регистрируется автоконфигурацией. Интерфейсы `adzercms/contracts` помечает бандл ядра, а интерфейс из пакета модуля несёт атрибут `#[AutoconfigureTag]` в `src/` этого пакета.
- Если действие или операция не может выполниться, она отказывает через `AdzerCMS\Contracts\Refusal`: в отказе есть причина для человека и маршрут с параметрами, где эту причину можно устранить. Строкой операции не отказывают, а страницы ведут по маршруту отказа и не разбирают текст причины.
- Шаблоны вида, у которого включён один модуль, доступны ещё и по ключу вида: `@Theme`, `@Admin`, `@Cabinet`. Другие модули обращаются к шаблонам по ключу вида, а не по пакету конкретного модуля.
- Страница модуля функции отдаёт только своё содержимое. Каркас, навигация и компоненты интерфейса приходят из темы по имени шаблона, и страница их разметку не повторяет.

## Код

- Движок работает на MySQL, MariaDB и PostgreSQL. Запросы пишутся на DQL или через построитель запросов DBAL. Таблицы, колонки и псевдонимы не называются зарезервированными словами, а миграции не указывают collation.
- Миграции пишутся по правилам раздела [Миграции](module-development.ru.md#миграции). Миграция относится к набору того пакета, которому принадлежит изменяемая таблица. Значения в ней — литералы, а номер версии не совпадает с номером из другого набора. Миграция пишется после кода, которому она нужна.
- Список загружает строки, значения модулей и вложенные коллекции одним запросом на страницу, а не запросом на каждую строку.
- Деньги хранятся в `DECIMAL` и считаются через `bcmath`, а выводятся денежными помощниками ядра.
- Текущее время берётся только из Symfony Clock: `now()` и `DatePoint` в коде, `now()` в шаблонах, `sleep()` часов — для ожидания.
- Любой текст, который видит человек, — ключ каталога перевода своего пакета в формате ICU MessageFormat; запасной язык — английский. Контракты принимают `TranslatableInterface`. Сообщения для разработчиков, вывод консоли и тексты гейтов пишутся по-английски и не переводятся.
- Запрос, который что-то меняет, передаёт токен CSRF в поле `_token`. В именах полей формы нет точек.
- Content Security Policy разрешает только собственный источник сайта; модуль добавляет свои источники через `ContentSource`. Обработчики событий живут в файлах скриптов и находят элементы по data-атрибутам. Скрипты — ES-модули в `public/` пакета, сторонние библиотеки подключаются через `importmap.php` пакета.
- Файлы, которые создаёт приложение, лежат в каталоге из параметра `adzercms.files_dir`; дерево кода приложение только читает.
- Консольная команда получает текст или секрет только через stdin по своему флагу и никогда — аргументом.
- Задание по расписанию завершается с ненулевым кодом, только когда не справилось само. Состояние внешних объектов оно сообщает в выводе.
- Сервис, который копит ответы или сущности на время запроса, реализует `ResetInterface`.

## Гейты

Хук pre-commit запускает те же гейты, что и у экземпляра (раздел [Git и обновления](installation.ru.md#git-и-обновления)), включая проверку, что текущее время не берётся в обход Symfony Clock. Кроме того, он не пропустит коммит, если:

- `README.md` или файл в `docs/` изменён без перевода `*.ru.md`;
- из двух файлов, одинаковых в `HEAD`, — в `packages/skeleton/` и по тому же пути в корне — изменён только один.

`vendor/bin/adzercms-check` проверяет всё дерево: стиль кода, PHPStan на уровне из `phpstan.dist.neon`, XLIFF, ICU, Twig, ключи каталогов и зависимости каждого пакета. Находку PHPStan исправляют в коде, а не через `ignore` или baseline. [CI](../.github/workflows/ci.yml) запускает проверки и все наборы тестов на MySQL, MariaDB и PostgreSQL со всеми поддерживаемыми версиями PHP при каждом push в `main` и в каждом pull request.

## Тесты

- Набор тестов — это пакет, и называется набор ключом своего модуля; все наборы перечислены в `<testsuite>` файла `phpunit.dist.xml`. Без `--testsuite` запускается только набор по умолчанию, и `--list-suites` показывает только его. Поэтому запускайте по имени набор изменённого пакета и наборы пакетов, которые им пользуются.
- Набор выбирает модули так, как описано в разделе [Тесты](module-development.ru.md#тесты) модуля; остальные виды остаются пустыми.
- Если ожидание теста опирается на поле, колонку, данные или сообщение модуля, тест живёт в пакете этого модуля. Тест ядра или модуля функции должен проходить с любым модулем вида; нужный ему модуль вида подключается как фикстура окружения тестов: `config/services_test.php` в корне и бандлы-фикстуры тестов ядра.
- Каждый тест идёт в транзакции, которая откатывается после него, поэтому тесты не полагаются на номера записей. Тест миграций ядра накатывает миграции на пустую базу и сверяет схему с метаданными.
- Помощники тестов ядра: `SchemaTestCase` — основа тестов с базой, его `reread()` перечитывает сущность, записанную запросом; трейты `Browser` (токен формы, вход, второй браузер, фрагменты, отправка форм, ячейки списков, плитки, всплывающие уведомления, загрузка файлов), `Container` (типизированные сервисы, параметры, команды, переведённые фразы), `Queries` (`assertListingKeepsItsQueries()` против N+1), `Configuration` (настройки экземпляра), `Delivery` (отправленные письма и сообщения), `Accounts` (учётные записи); `HttpAnswers` подставляет ответы внешних сервисов в `MockHttpClient`.
- Заглушка внешней системы отвечает так же, как отвечает живая система, включая её отказы.
- День сценария задаёт `mockTime()` часов: момент передаётся строкой в часовом поясе PHP.
- Обход экранов в `tests/browser/` проходит админку и кабинет живого экземпляра на узком и широком экране: `tests/browser/run.sh` с переменными `ADZERCMS_URL`, `ADZERCMS_LOGIN` и `ADZERCMS_PASSWORD` оператора. Страница не проходит, если вёрстка поехала, ответ пришёл с ошибкой, в консоли есть ошибка или `id` повторяется. Формы, которые что-то меняют, обход не отправляет.

Подводные камни:

- Сервис подменяется один раз и до того, как контейнер к нему обратится.
- `KernelBrowser` поднимает новый kernel между запросами, и подменённый сервис вместе с полученной раньше сущностью теряются. Удержите kernel через `disableReboot()` или берите запись из контейнера текущего запроса.
- Слушатель Doctrine не должен зависеть от сервисов, которые подменяет тест: его создаёт первый flush.
- Symfony CssSelector не понимает `:has()`.
- Фрагмент списка запрашивается с заголовком фрагмента: сама страница отдаёт только место под него.
- Письма считаются только по последнему запросу: переход по redirect обнуляет счётчик.
- Если находка PHPStan пропадает после очистки `tmpDir`, это устаревший кеш: удалите `tmpDir`.
