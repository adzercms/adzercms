# Модули

[English](modules.md) | Русский

Модуль — пакет Composer типа `adzercms-module` с бандлом Symfony. Одни модули добавляют сайту функции, другие отвечают за заменяемую часть: админку, личный кабинет, тему, вход через сервис, отправку SMS, бота мессенджера, капчу, счётчик аналитики.

## Подключить модуль

Установите пакет и впишите имя модуля в переменную окружения нужного вида в `.env.local`:

```sh
composer require acme/shop acme/pigeon
```

```dotenv
MODULES=Shop
SMS_MODULES=Pigeon
```

Имя модуля — имя класса бандла без `Bundle`: у `ShopBundle` это `Shop`.

| Переменная | Что подключает | Сколько |
|---|---|---|
| `MODULES` | функции сайта | несколько |
| `ADMIN_MODULE` | админку | один |
| `CABINET_MODULE` | личный кабинет | один |
| `THEME_MODULE` | тему | один |
| `LOGIN_MODULES` | вход через сервис | несколько |
| `SMS_MODULES` | отправку SMS | несколько |
| `BOT_MODULES` | ботов мессенджеров | несколько |
| `CAPTCHA_MODULES` | капчу | несколько |
| `ANALYTICS_MODULES` | счётчики аналитики | несколько |

Несколько модулей перечисляются через запятую. Модули функций могут добавлять свои виды со своими переменными.

Затем обновите базу:

```sh
bin/console doctrine:migrations:migrate
```

Установленный, но не подключённый модуль ничего не добавляет: ни сервисов, ни адресов, ни команд, ни таблиц. Если имя модуля неизвестно или не подключён модуль, без которого он не работает, сборка останавливается и показывает доступные имена.

## Подключить модуль из админки

Раздел «Расширения» админки открывается всеми пакетами каталога, следом идёт вкладка на каждый тип, который есть в каталоге: модули, интеграции, темы, шаблоны сайтов, мини-приложения; темы показываются карточками. Тип, порядок и ссылку на демо даёт каталог расширений adzercms.com; настройка `modules.store` вкладки «Общие» направляет сайт в другой каталог того же формата. Пакет, которого в каталоге нет, идёт после перечисленных по имени, а тип берёт от своего вида: тема — тема, модуль другого вида — интеграция, модуль функции — модуль.

У каждого пакета есть кнопки действий: установить, обновить, удалить, включить, выключить. Кнопка подаёт операцию, а задание `adzercms:modules` исполняет одну операцию в минуту. У операции остаются исход и вывод ошибки.

- Установка, обновление и удаление запускают Composer на копии сайта, которую делает [Composer Stager](https://github.com/php-tuf/composer-stager). Сайт получает результат, только если Composer отработал без ошибок: задание переносит его в сайт и обновляет сайт под одним удержанием. Обновление пакета движка обновляет все пакеты `adzercms/*` вместе
- Включение и выключение проверяют новый список модулей так же, как сборка, обновляют сайт с ним и только потом записывают переменную: в `.env` на сайте под git, иначе в `.env.local`. На сайте под git переменная в `.env.local` отказывает операции: перенесите её в `.env`
- На сайте под git задание коммитит изменение успешной операции, а хуки репозитория выкладывают его, как любой коммит. Сайт с незакоммиченными правками отказывает операциям и называет файлы
- Версия с отметкой «проверен» прошла автоматическую проверку модулей движка; установка и обновление на версию без отметки просят подтверждения
- Установка модуля включает его той же операцией: после Composer новый список модулей проверяется на копии, а при отказе списка сайт не меняется. Установка и включение модуля вида, у которого модуль один, заменяют включённый после подтверждения с его именем
- Удаление включённого модуля выключает его той же операцией; если от него зависит включённый модуль, операция отказывает до запуска Composer
- У включённого модуля админки нет кнопки выключения: его заменяет включение другого модуля админки
- Установленную невключённую тему можно посмотреть до включения. Операция собирает сайт с этой темой рядом с действующим, без миграций и без правки `.env`; затем кнопка предпросмотра открывает сайт в этой теме только вам, а плашка внизу страницы возвращает обратно. Предпросмотр у сайта один: новый, обновление сайта или включение темы снимают его. У темы со своими миграциями предпросмотра нет

## Подключить свои источники модулей

Вкладка «Источники» раздела «Расширения» принимает адрес закрытого репозитория Composer либо модуль, загруженный ZIP-архивом. Каталог подхватывает их в течение минуты.

- Токен репозитория вводится в диалоге учётных данных его строки. С логином Composer отправляет HTTP Basic, без логина — Bearer-токен. Учётные данные принадлежат хосту: все репозитории одного хоста пользуются ими вместе
- В ZIP-архиве нужен `composer.json` в корне либо в единственной папке верхнего уровня, с именем пакета и стабильной версией. Новая версия пакета — новый архив
- Пакет из ZIP главнее репозиториев, а ваши репозитории главнее Packagist
- Перед каждым запуском Composer задание записывает ваши источники в `repositories` файла `composer.json` под именами с приставкой `adzercms-`

## Включить вход, SMS, бота, капчу или счётчик

Такой модуль работает, когда он включён и заданы его ключи доступа. Настройки называются `<вид>.<модуль>.<поле>`:

```sh
bin/console adzercms:setting
bin/console adzercms:setting sms.pigeon.enabled 1
printf '%s' "$PIGEON_TOKEN" | bin/console adzercms:setting sms.pigeon.token --stdin
```

Первая команда показывает все настройки. Секреты передаются только через stdin. Если модуль выключить, его ключи доступа сохраняются.

Для SMS и капчи используется первый включённый модуль по порядку в списке. Входы через сервисы, боты и счётчики работают все, какие включены.

Включённый счётчик добавляет внизу страниц плашку о cookie: счётчик работает с первой страницы, плашка называет сервисы счётчиков, ссылается на политику обработки данных из настройки `legal.privacy_url` и несёт одну кнопку «Принять». От cookie посетитель отказывается в настройках браузера. Администраторы и подменённые записи не получают ни плашки, ни счётчиков.

## Продавать на OPOTOPO

Модуль `opotopo` выгружает каталоги других модулей объявлениями продавца на площадку [OPOTOPO](https://opotopo.com) через её Seller API: новые позиции становятся объявлениями, изменённые обновляются, а объявления позиций, которых больше нет в каталоге, уходят в архив. Модуль предлагает свой каталог, только если `opotopo` установлен.

```sh
bin/console adzercms:setting opotopo.url https://api.opotopo.com
printf '%s' "$OPOTOPO_KEY" | bin/console adzercms:setting opotopo.key --stdin
bin/console adzercms:setting opotopo.organization "$OPOTOPO_ORGANIZATION_ID"
bin/console adzercms:setting opotopo.publish 1
```

- `opotopo.url` — адрес Seller API
- `opotopo.key` — ключ из раздела «Разработчикам» аккаунта OPOTOPO; нужные ему разрешения перечислены в [руководстве клиента на PHP](https://opotopo.com/knowledge/developers/klient-na-php)
- `opotopo.organization` — организация продавца; без неё объявления заводятся от организации ключа, у личного ключа — от его владельца
- `opotopo.publish` — отправляет объявления на публикацию после каждого изменения; если выключить, новые объявления остаются черновиками

Выгрузку запускает [планировщик](installation.ru.md#планировщик). Позиции, которые площадка отклонила, перечислены с причиной в выводе задания, а при модуле `support` — в ежедневном перечне дел операторов, пока не уйдут успешно.

## Свой модуль для одного сайта

Положите его в каталог `modules/`: шаблон проекта подключает `modules/*` как path-репозиторий, и `composer require` находит модуль по имени пакета.
